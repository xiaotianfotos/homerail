# E2E Fix：纠正 Codex 依赖

基线：#308 合入后的 main，分支 `codex/e2e-fix-local-design`。
本次按维护者明确的职责划分纠正编排：调用者提供既定设计，本地模型开发，
其他独立模型审查 PR，反馈意见驱动继续修改。Codex 不属于正常运行依赖。

## 实现

- 新 prepare 入口要求 `design.strategy`，拒绝 `host_codex`。授权路径来自冻结配置。
- 工作流只有 Fixer 和三个 Reviewer 模型角色；没有 Planner、候选 Judger 或 CI Judger。
- 可信测试通过后先发布或更新同一个 PR，再审查该 PR 的固定候选与测试证据。
- 测试失败、审查票数不足和 CI 失败直接成为下一轮 Fixer 的反馈，设计摘要始终相同。
- 多票审核直接决定是否通过，程序同时检查独立会话、完整报告、测试和同 head CI。
  少数反对意见保留，不增加额外语义否决、不伪造 Judger 的“驳回”记录。
- 旧冻结任务保留原来的执行与证据协议，不热切换旧运行；新入口不再生成旧编排。
- 不增加 token 总消费限额。未知副作用保留现场，连续停滞仍可暂停。

## 验证

定向测试已通过共享门禁 36 项、准备与原生阶段 10 项。原生场景使用真实 Git、
Docker 测试和 Manager 图执行器，模型与 GitHub 使用明确的替身，不冒称真实模型演练。

覆盖：首次真实断言失败 → 第二轮过测但 PR 审查拒绝 → 第三轮更新同一 PR 通过；
CI 失败自动返修；两票通过且少数异议原文保留；CI 未知暂停；连续失败暂停。
断言所有模型派发均为 Fixer/Reviewer、PR 已发布才审查、每轮设计 hash 不变、
会话全部独立、无宿主 Codex 目录或 Planner/Judger 产物。

完整 CI 与最终实现 PR 的验证结果在完成后记录；只提交一个纠正 PR，不创建测试 PR。

- 原提交的完整本地 CI 通过；独立模型审查为一票通过、两票修改。
  三条发现对应两个问题，均在本 PR 修正：审核证据误标完整源码；
  发布后才检查新增上下文大小，可能留下无法继续的已发布 PR。

  无法容纳时尚未调用 GitHub 发布程序。

  已验证旧实现会在源码覆盖声明处失败，新实现通过。另有无法压缩的完整/
  已投影输入零发布调用、最大 PR 编号边界测试。

  审查被重叠策略拒绝。调整同 PR Actions 并发策略为等待，保留原结果收集。
  手工取消或跨 PR 的全局准入冲突不在此项修复的保证范围内。
